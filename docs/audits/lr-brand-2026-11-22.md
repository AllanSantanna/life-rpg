mantendo as verificações de preservação e ausência de `skipWaiting`.

As auditorias usam Playwright instalado em `/tmp`, sem dependência nova no app.
Os relatórios completos e as capturas adicionais estão em `/tmp/life-rpg-lr/`.

Para repetir a verificação da troca real de marca, prepare um build isolado da
base anterior à identidade LR (`67e7dcd`), sem checkout ou alterações da main:

```bash
mkdir -p /tmp/lr-previous
git archive 67e7dcd | tar -x -C /tmp/lr-previous
ln -sT /caminho/absoluto/life-rpg/node_modules /tmp/lr-previous/node_modules
(cd /tmp/lr-previous/apps/web && node /caminho/absoluto/life-rpg/node_modules/vite/bin/vite.js build)
npm run build
PLAYWRIGHT_MODULE=/caminho/para/playwright/index.mjs node scripts/audit-brand.mjs
```

`PWA_PREVIOUS_DIST` permite apontar para outra pasta do build anterior; o script
serve os dois builds apenas em loopback e usa um contexto descartável.

## Limitações e revisão

O ambiente não disponibilizou WebGL; a auditoria visual usou a alternativa 2D
existente. Não houve validação manual em Safari/iOS, janela standalone ou
launcher real de celular. O cache de ícones no launcher é controlado pelo
navegador/sistema, sem prazo garantido de atualização. Nenhum storage real foi
apagado ou modificado para atualizar a marca.

O build conserva os avisos conhecidos de chunks maiores que 500 kB. Não se
alteraram limites ou testes para ocultá-los.

Os checklists de implementação e revisão foram conferidos: escopo visual,
componentes/tokens existentes, acessibilidade, responsividade, preservação dos
dados, documentação, diff e staging seletivo. Campos, validações, comandos,
backend, regras de XP/classes/Radar e mecanismos de backup não precisaram de
alteração. A publicação da branch foi autorizada no pedido. Após a publicação, o usuário
autorizou integrar todas as alterações desta tarefa diretamente à `main` e
publicá-la no GitHub, substituindo a etapa de PR. As branches anteriores
permanecem preservadas; sua exclusão não foi autorizada.
